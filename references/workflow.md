# 项目没有既有流程时的开发约定

## 推进与角色

需求对齐 → 具体任务书 → 必要独立方案审查 → 核对用户对当前小步的明确授权 → 实施与自检 → 必要独立检查和发现修复 → 用户查看。

核对已有明确授权即可，不要求用户为同一授权重复回复。尚无当前小步的实施授权时只做已授权的调查或方案工作；用户指出问题、询问原因不自动等于允许修改。进入下一小步或实质变更范围、口径、接口、结构、关键路径和验收时才重新确认。已授权的小步内部不断开成多个用户门槛。

若 Claude 正在牵头，Codex 按现有任务书实施，不擅自接管；用户指定 Codex 牵头或原牵头方不可用时，Codex 承担拆解、推进与验收。角色安排与检查通道按实际可用工具核实；不要求安装 Claude 或任何指定服务，不擅自换账号、计费方式或供应商。

## 任务书与检查

任务书写清用户收益、可见产物、允许/禁止的改动、验收、预计轮数和停止点。工程验收必须有可重复执行的命令与期望结果，纯文档可用核对清单；查看入口另列。

| 级别 | 适用 | 必要检查 |
|---|---|---|
| L0 | 不影响运行的纯文档/规则文本 | 一次未参与产出的独立审查 |
| L1 | 代码、配置、脚本等运行改动 | 编码前独立方案审查；之后独立测试、独立代码审计、独立回归分别用未参与对应产出的新会话 |
| L2 | L1 中涉及真实数据、迁移、生产、权限、算法或对外/财务口径 | L1 全部，另加目标环境验证和用户验收 |

这些级别用于开发变更，不把普通问答和简单内容编辑升级成工程项目。现有项目有更具体约定时先读其约定；不能因缺外部通道就自签独立结论。

独立检查优先相对实施方的跨模型新会话，仅在通道实际不可用、额度不足或无法完成必要检查时回退未参与产出的同模型新会话，记录原因和局限。L0 可直接使用独立同模型会话。硬性跨模型要求不能用同模型冒充满足。方案作者不能审自己的方案；审查者参与修改后要换独立者复核。自检和牵头验收不代替独立结论。

检查任务包给原始需求、任务书、明确对象版本/未提交内容快照、允许命令和输出位置，并原样传递浏览器、网络、数据与写入限制。新会话不继承开发过程的预设结论；审计只读，测试和回归在隔离副本执行，不能改业务实现或验收基线。报告写真实模型/会话、参与情况、对象、环境、方法、原始证据、发现和未覆盖项；执行状态与结论分开。

必要检查未完成、失败或阻断发现未闭合时不报全部完成。保留原始发现与复核；实施方不能单方面删除、降级或接受阻断项。没有检查通道时继续有权限的工作，保全进度并明确受阻项，不伪造通过。

## 实施、真实性与止损

- 先核对真实仓库与远端主分支，基于核实后的主分支建立隔离工作区，不覆盖他人的脏目录；获取远端失败时明确基线未核实。
- 模拟、替身、场景判断与真实服务验证分开；只声称证据支持的范围，不把聊天承诺当工具已执行。
- 工程接口、权限、数据口径遵循成熟规范与项目契约，优先单一来源，避免复制业务规则；按影响验证异常和既有行为。
- 同一阻塞连续 3 次尝试/派发没有业务进展，或实际轮数超过预计 2 倍，停止无效循环；报告事实、根因判断和 2–3 个可行选项。纯技术选择附建议后自行处理，业务/范围/验收/授权取舍才请用户决定。
- 只清理由证据确认属于本任务的临时资源；不以进程名称批量结束他人任务，不清理个人浏览器或无归属的缓存/卷。

## 交付

正文讲清结果、需要用户做什么、实际验证和未验证部分；技术证据放附录。更新项目当前状态和单元记录，中断时写明停在哪、下一具体动作和未完成检查。若项目有流程检查脚本，收尾运行并如实报告；没有则按记录清单人工核对，不宣称安装本包就拥有 CI、hook 或真实的自动门禁。
