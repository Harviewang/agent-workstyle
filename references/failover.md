# 故障与接替

当前牵头方负责观察可见信号、保存检查点、调整分工。按正常调度表 → 故障覆盖 → 单厂回退的顺序决定下一角色；切换后重新排除参与对应产出的会话，遵守 [独立性底线](workflow.md)。换模型与换调用器是不同动作，不推断更换同厂档位一定恢复额度。

| 可见信号 | 动作 | 记录与边界 |
|---|---|---|
| 偶发超时或单次错误 | 原入口至多重试一次；仍失败再切换已可用入口/厂商 | 记录两次实际结果，不把超时当成功 |
| 明确额度耗尽或限流提示 | 保存产出与未完成检查，选可用厂商和能覆盖任务的档位 | 仅按提示判断；没有余额信息记“未知” |
| 明确鉴权、资格或权限错误 | 标该通道不可用，选已有授权的其他通道 | 不换账号、计费方式，不绕过权限 |
| CLI/调用器启动失败 | 核对本机帮助，选已安装且已验证的替代入口 | 不照搬 agy 与 Gemini CLI 的参数，不把换入口当换厂商 |
| 实施方不可用 | 核对已落盘代码、任务书、命令证据，再交接同一范围 | 记录“接替实施”；低档接替标“降级接替”，牵头加强验收 |
| 审查方不可用 | 重选未参与产出的新会话，优先作者外厂 | L1 同厂回退写原因；L2 缺外厂停在“已修改、待审” |
| 所有云端通道不可用或断网 | 保全现场，只运行已准备好且获准的本地检查 | 不假设仍有可用云端助手，不宣称检查通过 |
| 原因/额度信号不可见 | 记“未知”，依据实际可执行能力处理 | 不由 token 用量推算余额，不猜服务故障原因 |

每次切换在项目当前记录追加一行：`角色｜原厂商/档位/入口 → 新厂商/档位/入口｜可见信号（或未知）｜对象与已落盘进度｜独立性影响/回退标记｜下一检查`。不另建竞争台账，不把私人型号、账号或原始错误中的秘密写进公开资料。

耗时派发前先保存最小检查点。接替者先读真实产出和证据，不把前任已写结论当作已执行验收。同一阻塞连续三轮无业务进展，或实际轮数超过预计两倍，停止循环并汇报事实与选项。
