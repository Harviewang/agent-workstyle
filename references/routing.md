# 按可用厂商与能力分配角色

C = Claude，X = Codex，G = Gemini；组合表示当前实际可用厂商，不代表型号或账号。先用本表正常分工，再按 [故障覆盖](failover.md) 排除不可用项，最后应用 [单厂回退底线](workflow.md)。每次重选都排除参与对应产出的会话；厂商可相同，会话必须独立。

## 能力档位

| 档位 | 合适职责 | 使用边界 |
|---|---|---|
| 顶档 | 高风险方案、复杂判断、争议升级 | 可用时升级；稀缺档位不进入必经组合 |
| 主力 | 牵头、实施、独立测试/审计/回归 | 常规完整工程工作；按实际能力选择 |
| 日常 | 边界清楚的实现、常规检查 | 不足以覆盖风险时升档或标受阻 |
| 杂活 | 格式、机械整理、清单核对 | 不单独承担复杂工程验收 |
| 看材料 | 长材料提取、整理证据 | 摘要作导航，不能代替审查原始产出 |

优先使用主力档；牵头按风险决定是否升顶档。个人型号映射只在私有档案维护，示例见 `profiles/example.toml`。同厂不同档位不自动等于跨模型；型号不明时独立性只认新会话。

## 七种组合

表中“作者外厂”是相对对应方案或代码的作者而言。方案作者不能审自己的方案。表内审查者是候选厂商，每项检查都另开未参与对应产出的新会话；L1/L2 的独立测试、代码审计、回归各用不同新会话。默认分工可随用户指定和实际能力调整，独立性底线不变。

| 组合 | 牵头 | 实施 | L1 审查者 | L2 审查者 | 降级标注与停止线 |
|---|---|---|---|---|---|
| C | Claude 主力 | Claude 主力新会话 | Claude 新会话 | 缺外厂；Claude 新会话仅作回退候选 | L0/L1 标“同厂回退”；L2 到“已修改、待审”，用户明确接受同厂结论才可完成 |
| X | Codex 主力 | Codex 主力新会话 | Codex 新会话 | 缺外厂；Codex 新会话仅作回退候选 | L0/L1 标“同厂回退”；L2 到“已修改、待审”，用户明确接受同厂结论才可完成 |
| G | Gemini 主力 | Gemini 主力新会话 | Gemini 新会话 | 缺外厂；Gemini 新会话仅作回退候选 | L0/L1 标“同厂回退”；L2 到“已修改、待审”，用户明确接受同厂结论才可完成 |
| CX | Claude 主力 | Codex 主力 | Claude 代码审查；Codex 方案审查 | 至少一名作者外厂：代码选 Claude，方案选 Codex | 外厂不可用时 L1 标“同厂回退”及原因；L2 按单厂停止线 |
| CG | Claude 主力 | Gemini 主力 | Claude 代码审查；Gemini 方案审查 | 至少一名作者外厂：代码选 Claude，方案选 Gemini | 外厂不可用时 L1 标“同厂回退”及原因；L2 按单厂停止线 |
| XG | Codex 主力 | Gemini 主力 | Codex 代码审查；Gemini 方案审查 | 至少一名作者外厂：代码选 Codex，方案选 Gemini | 外厂不可用时 L1 标“同厂回退”及原因；L2 按单厂停止线 |
| CXG | Claude 主力 | Codex 主力 | Gemini 优先；Claude 可审代码，Codex 可审方案 | 至少一名作者外厂：Claude 方案选 Codex/Gemini；Codex 代码选 Claude/Gemini | 一家故障重选剩余双厂组合；只剩一家按单厂停止线并标原因 |

L0 均只需一次未参与产出的新会话审查；单厂标“同厂回退”。多人或多会话不能替代跨厂，也不能替代独立测试、代码审计、回归的覆盖。牵头验收与实施方自检不签发独立结论；项目有更严格跨厂要求时，用户接受同厂回退也不自动解除项目要求。
